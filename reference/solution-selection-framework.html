Khung chọn giải pháp AWS

Không chọn dịch vụ trước. Chuyển đề bài thành các ràng buộc, rồi chọn phương án đáp ứng toàn bộ ràng buộc với ít vận hành nhất.

1. Dữ liệu đến thế nào?

Batch, streaming, request/response, hay file transfer?

2. Cần làm gì?

Lưu, query, transform, orchestration, catalog, hay phân quyền?

3. Ràng buộc nào quyết định?

Latency, replay, thứ tự, least privilege, chi phí, hay ít vận hành?

4. Cái gì bị loại?

Phương án thiếu dù chỉ một ràng buộc bắt buộc đều sai.

Ba lớp hay bị lẫn

Network: Có đường kết nối không? Ví dụ: VPC endpoint, route table, security group, port.

IAM: Principal có được gọi AWS API không? Ví dụ: Lambda execution role có kinesis:GetRecords hoặc dynamodb:PutItem.

Data authorization: Principal có được đọc/sửa dữ liệu bên trong dịch vụ không? Ví dụ: Redshift GRANT SELECT hay Lake Formation column permission.

Mẫu streaming có replay

Producer → Kinesis Data Streams → Lambda → DynamoDB
                │
                └─ retention đủ dài → consumer mới đọc lại từ thời điểm cần replay

“Replay” là ràng buộc chọn nguồn dữ liệu. Kinesis Data Streams giữ record trong thời hạn retention; Lambda đọc stream bằng event source mapping. Nếu đề yêu cầu xử lý lại record cũ, retention và điểm bắt đầu của consumer phải bao phủ thời điểm đó.

Loại nhanh các đáp án

  • Đề yêu cầu custom transform → phải có compute chạy code như Lambda hoặc Glue; destination không tự thực hiện logic đó.
  • Đề yêu cầu replay hoặc nhiều consumer → ưu tiên stream có retention và consumer độc lập.
  • Đề yêu cầu “least operational overhead” → ưu tiên managed integration trước EC2/ECS/KCL tự vận hành.
  • Đề yêu cầu private access → tách network access khỏi IAM permission.
